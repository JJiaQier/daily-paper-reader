## 摘要
学习优化（L2O）方法通过训练模型来预测解、热启动、分支决策或其他形式的求解器指导，从而加速重复优化。这些流程中一个关键但常被忽视的组件是特征函数，它将问题实例映射为机器学习模型的输入。现有的L2O方法通常依赖手工设计的特征，使得表示设计成为手动的，并且在各个领域基本固定。我们引入了FunL2O，这是第一个通过LLM驱动的程序演化来自动化L2O特征设计的统一框架。在FunSearch风格的循环中，LLM提出可执行的特征函数，而固定的评估过程会重新训练原始的L2O模型并衡量下游优化性能。我们在涉及解预测和热启动的线性与二次规划任务，以及使用GNN引导的后门分支和预测-搜索的混合整数优化任务上评估了FunL2O。在连续和离散优化任务以及四个LLM中，演化出的特征始终优于手工设计的表示。这些结果确立了LLM驱动的特征演化作为一种通用且有效的方法，用于自动化L2O中的表示设计。

## Abstract
Learning-to-optimize (L2O) methods accelerate repeated optimization by training models to predict solutions, warm starts, branching decisions, or other forms of solver guidance. A critical yet largely overlooked component of these pipelines is the feature function that maps problem instances to inputs for machine learning models. Existing L2O methods typically rely on hand-crafted features, making representation design manual and largely fixed across domains. We introduce FunL2O, the first unified framework for automating feature design through LLM-driven program evolution for L2O. In a FunSearch-style loop, an LLM proposes executable feature functions, while a fixed evaluation process retrains the original L2O model and measures downstream optimization performance. We evaluate FunL2O on linear and quadratic programming tasks involving solution prediction and warm-starting, as well as on mixed-integer optimization tasks using GNN-guided backdoor branching and Predict-and-Search. Across continuous and discrete optimization tasks and four LLMs, the evolved features consistently outperform hand-crafted representations. These results establish LLM-driven feature evolution as a general and effective approach to automating representation design in L2O.

## 1. 论文的核心问题与整体含义（研究动机和背景）

**核心问题**：学习优化（Learning-to-Optimize, L2O）方法旨在利用神经网络对大规模重复优化问题进行加速，但现有方法普遍依赖**手工设计的特征函数（feature function）** 来将优化实例转化为模型输入。这种手工特征设计方式存在三个突出问题：

- **手工性强**：特征表示的设计依赖研究者的经验和领域知识，缺乏自动化手段；
- **领域固定**：针对某一类问题设计的特征往往难以迁移到其他问题类型；
- **难以验证最优性**：特征表示的选择对模型表达能力与下游优化性能有显著影响，但学界缺乏系统性的自动化搜索方法。

**论文定位**：本文提出了 **FunL2O**，首个通过 **LLM引导的程序演化** 来自动设计 L2O 特征函数的统一框架。该框架将特征函数视为一段**可执行代码**，在语义契约约束下，由 LLM 提出候选程序，通过实际重训练 L2O 模型并测量下游优化性能进行筛选与迭代进化。

**整体含义**：该工作确立了特征函数设计作为 L2O 中一个**独立且可自动化**的环节，并展示了 LLM 驱动特征演化作为一种通用、有效的方法，在连续优化和离散（MILP）优化任务上均能一致地超越手工特征表示。

## 2. 论文提出的方法论

### 2.1 核心思想

FunL2O 采用 **FunSearch 风格**的 LLM 程序演化循环：LLM 提议可执行特征函数 → 语义契约验证合法性 → 在原始 L2O pipeline 中重训练模型并测量下游优化性能 → 将性能反馈给 LLM 迭代优化。整个搜索过程**只改变特征函数**，模型架构、训练目标、数据、求解器等均保持固定。

### 2.2 问题形式化

L2O pipeline 可表示为：

\[
x \xrightarrow{\phi} X \xrightarrow{M} a \xrightarrow{S} \hat{y}
\]

其中 \(\phi\) 为特征函数，\(M\) 为学习模型，\(a\) 为预测解或求解器指令，\(S\) 为下游求解器。

特征设计问题定义为：

\[
\phi^\star \in \arg\min_{\phi \in \Phi_P} \rho_P(\phi)
\]

其中 \(\rho_P(\phi) = (b_P, v_P, q_P)\) 为词典序排名键（feasibility → infeasibility degree → objective/solver work）。

### 2.3 关键技术细节

- **语义特征契约（Semantic Feature Contracts）**：定义候选函数的合法输入字段（\(U_P\)）、输出规范（\(Z_P\)）、不可违反的不变量（\(I_P\)）以及可执行验证器（\(V_P\)）。验证器执行静态检查（安全环境、禁止文件/网络访问）与动态检查（签名、结构、维度、数值有限性、保留种子通道）。

- **标准化提示构建**：统一提示模板包含共享指令、语义契约、共享特征词汇（原始量、尺度、残差、曲率等）、精英函数上下文与反馈。

- **L2O-in-the-Loop 搜索**：从手工特征 \(\phi_0\) 初始化搜索记忆；每代由 LLM 生成 6 个候选，经过验证后并行训练与评估，更新记忆并按排名选取 Top-2 精英进入下一代。每代候选独立训练评估，可并行化。

## 6. 论文的主要结论与发现

1. **一致改进**：在 8 个 L2O pipelines 上，演化的特征函数一致优于手工特征表示：
   - IPM-MPNN：目标间隙降低 **16.4%–49.4%**（5 个 LP 分布全部改善）；
   - FSNet：9 个主要任务中改善 6 个并匹配其余 3 个，非凸 SOCP 间隙从 933.85% 降至 141.28%，可行性从 0.25 提升至 1.00；
   - PDHG-Net：迭代节省从 42.44% 提升至 51.05%，时间节省从 34.03% 提升至 39.28%；
   - Learning to Pivot：枢轴计数几何均值降低 **26.2%**；
   - Predict-and-Search：三个域的最终原始间隙和原始积分均显著降低；
   - Learned Backdoors：MIS 平均墙钟时间较默认求解器降低 **55.2%**，胜率最高达 49%。
2. **结构有价值而非单纯宽度**：匹配宽度随机控制显示 FunL2O 在 5/6 个任务上优于随机特征，说明增益来自语义结构而非维度增加。
3. **演化反馈有效**：PDHG-Net 上，独立采样提升 8.53 个百分点（35.89→44.42），而加入演化反馈后进一步达到 52.23%，额外提升 7.81 个百分点。
4. **与 LLM 提供商无关**：四个 LLM 中三个（Claude、GPT、Gemini）在 15–17/20 个共享任务上均有改进，证明框架的通用性；更强的模型生成成功特征的可靠性更高。
5. **可解释性**：发现的程序可解析出有意义的优化关系——集合覆盖中的成本/覆盖率归一化、PageRank 中的行列质量不对称、SOCP 中的尺度不变归一化等。

## 7. 优点

- **首次统一框架**：将特征函数设计形式化为程序搜索问题，首次实现 L2O 特征设计的自动化；
- **接口通用性强**：语义契约机制使同一搜索程序无缝适配异构图、稠密张量、求解器状态等不同特征接口；
- **评估客观**：完全基于重训练后的下游优化性能度量，而非 LLM 的主观判断；
- **隔离变量**：严格保持模型、训练、求解器不变，清晰隔离特征函数的影响；
- **公平实验设计**：验证/测试集分离、三种子配对、规范化改进率计算、基线保持候选资格，统计设计严谨；
- **部署零成本**：选中函数为普通预处理代码，部署时无需 LLM；
- **可解释性**：演化程序可直接检视，揭示原表示缺失的结构关系。

## 8. 不足与局限

- **离线搜索成本高**：每次搜索约需 12 GPU 小时 + 13.3 CPU 小时 + $192 API 费用，在大型 pipeline 上可能不经济；虽可在重复优化场景中摊销，但对一次性优化问题不适用；
- **对 LLM 能力有依赖**：较弱模型（DeepSeek-Math-V2）在连续优化中仅改进 6/20 个任务，明显弱于其他三个模型（15–17/20），说明搜索质量受提议模型能力制约；
- **部分任务无改进**：FSNet 的 3 个非凸 QP/QCQP 任务、DC3 的若干任务改进幅度有限（2–4%），非凸 QP 上完全无改善，说明对原始特征已较优的任务增益有限；
- **对照体系不完整**：未与遗传规划、AutoML 特征工程、固定特征库等系统的系统比较，未能确立对任意程序搜索基线的普遍优势；
- **搜索预算有限**：每搜索仅 48 个候选 + 3 次修复尝试，可能不足以探索大规模特征空间；
- **报告方式**：连续优化的主表报告 4 个 LLM 的中位数，MILP 报告两个独立模型分别运行的结果，缺乏所有 LLM 在 MILP 上的完整交叉比较；
- **潜在过拟合风险**：虽然验证/测试分离缓解了过拟合，但演化过程可能隐式选择在验证集上表现好而泛化性不足的特征，论文未讨论验证集大小和代表性与搜索代数的关系。
